# Relay 笔记与附件自动命名规则

此规则适用于 `notes/` 下的知识笔记、图片和其他附件，供 ChatGPT 与 Codex 共同使用。目标是提升知识库检索体验，保护链接和用户原始资料。

## 识别候选

只有名称明显是默认或设备自动生成时，才考虑更名，例如：

- `未命名.md`、`Untitled 1.md`、`Pasted image 20261008.png`
- `Screenshot_20261008_135900.png`、`IMG_20261008_135900.jpg`、`微信图片_20261008...jpg`
- 随机哈希、UUID 风格但不具备内容含义的名称

**不要仅凭短名称就断定它是未命名**；已有业务名称、明确日期、用户自定名字等需要保留。也不要更改根目录 Codex 文件、脚本或配置。

## 命名规则

1. 先读取文件内容（文字）或查看真实图片（图像）。无法打开图片时不可猜测内容。
2. 使用中文的简短语义标题，尽量描述主题或作用。必要时加日期、项目名前缀；文件扩展名保持原样。
3. 避免非法路径字符 `/ \\ : * ? " < > |` 和重名；出现冲突时添加简短后缀。
4. 对图片，为所在笔记补充一行说明（如 `**图片说明：** ...`），或在同目录的附件索引 Markdown 中记录名称、相对位置、内容描述与来源。不能确认来源时留空。
5. 对已被笔记引用的文件，先搜索引用，再完成更名并更新 `![[文件名]]`、`[[文件名]]`、标准 Markdown 链接以及可能存在的路径。**确保链接正常再提交。**
6. 一次只操作已确认的候选文件；批量整理前给出清单。删除、覆盖和强制推送不属于本策略。
7. 含私人敏感信息的文件不得因“命名”自动公开、复制到不安全位置或发送给外部模型。

## 图片说明格式示例

```markdown
![[Obsidian-Git自动同步设置.png]]
**图片说明：** 安卓 Obsidian Git 的自动提交、推送和拉取间隔设置截图。
```

## Git 同步流程

- 手机 Obsidian 将附件保存在 `notes/03-Resources/Attachments/`，通过 Commit-and-sync 推送。
- ChatGPT/Codex 拉取最新提交，检查候选和引用，再实施安全改名。
- 改名完成并推送后，手机 Obsidian 执行 Pull，检查图片显示是否正常。
- 不要在手机未推送的同一文件上执行远程覆盖；遇到冲突先核对差异。

**说明：** 这份规则是 Relay 仓库内的工作约定，不是后台服务。只有当 ChatGPT 或 Codex 处理相关文件时才会执行，不代表无人值守持续监控。
