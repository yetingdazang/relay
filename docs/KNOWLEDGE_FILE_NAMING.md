# Relay 笔记与附件命名规则：仅处理新文件

本规则仅适用于新添加到 `notes/` 的文件，不会反复扫描历史知识库。供 ChatGPT 与 Codex 在用户请求整理或配置了入库处理流程时使用，**不是后台自动任务**。

## 增量处理和防重复

1. 从 `config/knowledge_naming_cursor.json` 读取上次检查的 Git 提交 SHA；初始位置是建立本规则时的仓库 HEAD。
2. 取得当前远端 `main` 的 HEAD，并使用 Git 提交差异（compare）找到从上次检查到本次检查之间 **状态为 `added`** 的文件；只保留 `notes/` 下的新增项。
3. 不扫描整个 `notes/` 的存量文件内容，也不把 `modified`、`renamed`、`removed` 状态当作新文件；用户明确指定旧文件时才例外。
4. 对新文件中明显有设备默认/自动生成名称的条目执行下面的安全检查；人工命名的新文件跳过，避免无谓分析。
5. 处理完成后将已检查的远端 HEAD 保存为新的 cursor SHA。即使没有新图片，也要在一次明确执行的增量检查后推进游标，避免下次重复检查。
6. 若并发提交或写入发生冲突，停止并重新读取最新游标和提交差异，绝不覆盖他人未同步的修改。若部分处理失败，记录失败项，不要错误宣称全部处理成功；未完成时不推进游标到遗漏这些项的位置。

## 默认名候选（仅新增文件）

- `未命名.md`、`Untitled 1.md`、`Pasted image 20261008.png`
- `Screenshot_20261008_135900.png`、`IMG_20261008_135900.jpg`、`微信图片_20261008...jpg`
- 无内容含义的 UUID / 哈希文件名

用户自己取的名字要保留。不要处理仓库根目录中的 Codex 任务、程序或配置。

## 安全命名与备注

- 先阅读实际文本或查看真实图片，不能查看时保持原名，不猜测内容。
- 根据主题生成简短中文名称，保留原扩展名；避免路径非法字符和重名。
- 为图片在对应笔记中增加简短说明，或者在附件索引 Markdown 中添加描述。不要随意重编码或修改原始图片二进制。
- 改名前要找到受影响的 Obsidian `![[...]]`、`[[...]]` 或 Markdown 图片链接。仅在需要修复引用时有针对性地搜索，并更新所有必要引用，确保图片不会因改名失效。
- 不要自动删除、覆盖、强制推送或公开私人资料。
- 无法识别内容的新增文件标记为跳过，不要在以后每次检查中重复尝试；只有用户要求时才重试。

## 操作流程

手机 Obsidian **Commit-and-sync** 上传 → ChatGPT/Codex 对比游标后新增文件 → 仅处理新默认名文件 → 提交安全修改 → 记录处理游标 → 手机 Obsidian Pull 查看。

若用户只是执行 Pull，没有 Push 到 GitHub，则远程不会出现手机本地新附件。不要把读取失败误判成图片不存在于手机。

当前不提供每次 Git push 自动触发命名的服务；需要另外部署调度程序才能无人值守运行。
