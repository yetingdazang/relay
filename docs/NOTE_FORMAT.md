# Relay 知识笔记默认排版规范

本规范供 ChatGPT 和 Codex **今后创建或整理** `notes/` 里的知识笔记、资料分析、项目总结时使用。默认格式参照 `notes/00-Inbox/小黑盒AI使用经验帖子.md`。

## 页面顺序（默认）

1. **标题与简要摘要**：以一级标题 `# 标题` 开始，下面用 Obsidian `> [!summary] 提要` 给出 2～5 句话（重点在于结论、为什么重要、适合何种用途）。
2. **可点击的目录**：紧接提要写 `## 目录`，用 Obsidian 原生章节链接 `[[#准确的标题|显示名称]]` 指向下文真实存在的二/三级标题；根据正文复杂程度使用层级嵌套。
3. **正文**：按逻辑分节，保留重要事实、步骤、例子、局限与可执行建议，段落清楚。正文中可按需要放来源链接、作者/日期、关键代码或对照表。
4. **原始资料与附件（最后）**：末尾放 `## 原始资料` 或 `## 原始长截图`，列出处、原始截图、PDF、文档及有关图片链接。对于图片资料用 `![[图片名.jpg]]`；此节须同时被目录引用。原图不用复制、不要自动重编码。

如果没有原始图片，不要硬造一个空图片区；可在文末放 `## 参考资料` 或 `## 来源`。如果是纯个人短便笺、待办或随手记录，可适当缩短，但经过 AI 整理为正式知识笔记后尽量使用上述结构。

## 执行细节

- 提要在文章开头，不要让大幅图片先于文字，也不要把原图插到提要前。
- 目录**必须可跳转**，不采用只有文本的假目录。目录项与标题逐字匹配；正文新增/重命名标题时同步调整目录。
- 有多个小节时使用 `##`、`###` 分级标题。过长目录可以只列主要章节和核心子章节，避免首页被目录占满。
- 不把原作者的说法、模型自述与 AI 衍生建议混写：区分“原文观点 / 个人分析 / 给 Relay 的建议”，注明来源或不确定性。
- 保持原有笔记中有意义的信息；不得为凑模板填充不真实内容、不得擅自删除截图或破坏 Obsidian 链接。
- 本规则只影响**今后新建**的笔记和用户明确要求重排的笔记；**不批量扫描/修改所有旧笔记**，避免 Git 冲突和 Token 浪费。
- 新文件命名依旧遵循 `docs/KNOWLEDGE_FILE_NAMING.md` 的增量原则；排版规则与命名规则彼此独立。

## 可复制模板

`notes/03-Resources/Templates/标准知识笔记模板.md` 提供了可在 Obsidian 中直接使用的 Markdown 模板。模板里的示例目录是占位内容，新笔记必须用真正的章节名称替换。
